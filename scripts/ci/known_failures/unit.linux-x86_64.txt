# 1. Upstream gives another result on x86_64 Linux, and the port gives that
#    same result there (regenerated expectations pass):

# The default NaN of x86 has its sign bit set (0.0 / 0.0, inf - inf,
# sqrt/ln of a negative number: fff8.../ffc00000 where aarch64 gives
# 7ff8.../7fc00000). The CBOR test builds its NaN as `0.0 / 0.0`.
data/cbor/cbor_test.mbt ("encode")
hayro/interpret/function/oracle_wbtest.mbt ("postscript programs match hayro-interpret")
typst/oracle_wbtest.mbt ("oracle: location keys: negative zeros and NaNs")
typst/oracle_wbtest.mbt ("oracle: floats: the bits of NaN values")
# Rust's f32/f64 math methods call the C library, whose results differ in
# the last place between glibc and Apple's libm: `tan`, `sin`/`cos` in
# svgtypes (19 of 114 transforms, 121 of 525 arcs), `sinf`/`cosf` in
# tiny-skia-path's rotations, the PostScript function of
# pattern_shading_type1_6.pdf in hayro (1 of 784 renderings).
