The revision’s new rules and claims leave these concrete issues:

1. **A — MAJOR: “Flags are complete” is false for element identities.**

   [§11.4, lines 776–783](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/docs/edsl-design.md:776) says nested modules were the sole unflagged omission. However, `Element::fingerprint` writes only `name()` and sets no flag; element-function fingerprints use that representation. See [value_hash.mbt:25](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/value_hash.mbt:25) and [value_hash.mbt:265](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/value_hash.mbt:265).

   `grid.cell` and `table.cell` are distinct handles both named `"cell"`: [elems_gen.mbt:1204](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/elems_gen.mbt:1204), [elems_gen.mbt:6655](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/elems_gen.mbt:6655). With equal function spans, they therefore have identical fingerprints and zero flags.

   Consequently, otherwise identical queried metadata containing `table.cell` versus `grid.cell` bypasses exact validation: [introspector.mbt:218](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/introspector.mbt:218) drops the comparator. A pure contextual callback alternating between those values according to the preceding query can falsely converge. This uses ordinary public element functions, without custom engine objects.

   **Fix:** Make element fingerprints distinguish actual element identities, or flag the omitted identity and require exact comparison. Add a recorded-query regression with equal-span `table.cell`/`grid.cell` values in metadata, and include this change in §18’s engine work.

2. **B — MAJOR: The new termination proof overlooks data traversed by leaf equality.**

   [§11.4, lines 819–832](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/docs/edsl-design.md:819) claims exact comparison visits only a subset of the fingerprint traversal, and therefore cyclic arrays cannot reach validation. But a tiling fingerprint reads its repr and frame item count, **without traversing frame contents**: [value_hash.mbt:103](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/value_hash.mbt:103). The prescribed comparison delegates to tiling equality, which traverses the frame: [memo.mbt:255](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/memo.mbt:255), [tiling.mbt:5](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/tiling.mbt:5), [frame.mbt:553](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/frame.mbt:553).

   A concrete admitted graph is a tiling whose frame contains a located metadata start tag whose value is a self-containing engine array. Engine arrays expose their mutable items, so the cycle can be constructed before compilation and then left untouched: [array.mbt:11](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/array.mbt:11). No frame needs to be reused after moving it.

   Build two separate such graphs and pass them through §13’s `Value::engine`. Their tiling fingerprints terminate and match, but comparison reaches tag-content equality and then recursive array equality, which has no cycle cutoff: [content.mbt:367](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/content.mbt:367), [ops.mbt:459](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/ops.mbt:459). Thus validation can recurse indefinitely even though both fingerprints terminated.

   **Fix:** Either reject cyclic engine graphs during lowering—including graphs hidden inside tiling frames—or make validation cycle-aware through every delegated equality traversal. Tracking only module pairs is insufficient. Add a termination regression for cyclic arrays hidden inside tiling-frame metadata, alongside the existing module-cycle test.
