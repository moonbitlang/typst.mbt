The revision’s new rules leave these concrete issues:

1. **MAJOR — The new module-validation rule can be bypassed entirely.**

   [§11.4](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/docs/edsl-design.md:768) retains exact validation only when fingerprint flags are nonzero, while promising recursive module comparison. But [Module::fingerprint_with_depth](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/value_hash.mbt:212) omits nested modules’ content and bindings without marking that omission lossy or propagating their identity flags.

   Two outer modules can therefore have equal fingerprints and zero flags while their equally named nested modules contain different host functions or gradients. Such values can enter through §13’s `Value::engine` and be stored in queried content. The recorder then drops the exact comparator at [library/introspector.mbt:218](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/introspector.mbt:218). The new recursive module rule never runs.

   **Fix:** Either fingerprint the complete graph with cycle handling and flag propagation, or mark truncated module hashes conservatively as lossy and potentially identity-bearing, then validate their contents recursively. Add a recorded-query test with differences hidden inside nested modules.

2. **MAJOR — The new resolved-grid comparison omits lossy line strokes.**

   [§11.4](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/docs/edsl-design.md:796) checks equal grid fingerprints plus cell bodies, fills and strokes. A `CellGrid` also contains explicit horizontal and vertical lines. Their strokes are hashed through the same lossy stroke representation: [library/grid_resolve.mbt:2466](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/grid_resolve.mbt:2466), [library/grid_resolve.mbt:2513](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/grid_resolve.mbt:2513).

   Two otherwise identical grids whose line paints use the distinct, equal-fingerprint gradients from [library/memo_wbtest.mbt:18](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/memo_wbtest.mbt:18) pass the specified comparison. Comparing only cells does not repair that fingerprint loss.

   **Fix:** Include both line arrays and exact comparison of their resolved strokes. Test equal-fingerprint grids differing only in an explicit line stroke.

3. **MAJOR — The new “finite DAG” termination argument does not cover the admitted engine values.**

   [§11.4](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/docs/edsl-design.md:802) explicitly rejects cycle detection because values supposedly cannot contain cycles. That is false for the public engine API admitted by `Value::engine`: [Module::new](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/module.mbt:22) retains its supplied scope, and [Scope::define](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/scope.mbt:397) mutates that scope. A caller can create a module, bind that module into its own scope, and then stop mutating it before compilation.

   Comparing two separately constructed such graphs recursively revisits the same module pair. No callback-time mutation is necessary. Acyclic imports and opaque EDSL nodes do not exclude this case.

   **Fix:** Make recursive validation track visited object pairs, or explicitly reject cyclic engine graphs at the escape-hatch boundary. Add a termination test; do not rely on the description-tree invariant for engine values.

4. **MINOR — The new structural dump loses labels on sequences and styled wrappers.**

   [§16.2](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/docs/edsl-design.md:1213) prints sequences as children and styled content as styles plus child; it prints a label only for “any other element.” Yet §4.2 deliberately permits labels on sequences and wrappers, and [Content::labelled](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/content.mbt:99) stores labels independently of element kind.

   Consequently, `Labelled(Seq(["a", "b"]), "x")` and the unlabelled sequence receive the same specified structural dump.

   **Fix:** Emit the label for every content node before branching into sequence, styled or ordinary-element encoding. Add labelled-sequence and labelled-wrapper twins.
