The revision introduces these concrete problems in its new rules and claims:

1. **A — MAJOR: The new “exact” convergence rule remains inexact through closure captures.**

   [§11.4, design:731](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/docs/edsl-design.md:731) accepts Typst closures solely by structural fingerprint. Those fingerprints recursively use the existing value fingerprints, including lossy ones. The repository already has two distinct gradients with identical fingerprints in [memo_wbtest.mbt:18](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/memo_wbtest.mbt:18).

   Put those gradients into otherwise identical closure captures: [value_hash.mbt:263](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/value_hash.mbt:263) hashes the captured scope, and the proposed closure shortcut accepts the resulting equal hashes. The gradient equality check is never reached. This needs no cryptographic collision and contradicts the claimed protection for lossy results.

   **Fix:** Compare closure code structurally, then recursively validate defaults and captured bindings, including host identities and lossy values. Use cycle-aware traversal where necessary. Fresh but structurally equivalent evaluator closures can still converge.

2. **B — MAJOR: Applying sequence-tail rules to variadic arguments changes document structure.**

   [§8, design:505](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/docs/edsl-design.md:505) includes “a variadic children array” among sequences lowered using `tail.styled_with_map(...)`.

   For `Table([SetText(...), "a", "b"], ...)`, that rule packages `"a"` and `"b"` into one styled content argument. The table constructor consumes each positional argument separately; ordinary content becomes **one cell**. See [element.mbt:411](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/element.mbt:411), [table.mbt:196](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/table.mbt:196). Wrapping individual arguments also needs care: header/footer recognition checks their outer element directly at [table.mbt:105](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/table.mbt:105).

   **Fix:** Limit sequence-tail rule semantics to `Document` and explicit `Seq`. Reject bare rule entries in variadic argument lists; authors can place rules around the whole table or inside an explicit cell-body `Seq`. Preserve one positional argument per variadic entry.

3. **C — MAJOR: The text-provenance test can report an incorrect offset as exact.**

   [§12.4, design:848](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/docs/edsl-design.md:848) checks original string length and downgrades transformed text when its glyph range no longer fits the string. That is insufficient.

   Paragraph collection inserts directional embedding characters before a differently directed text run and performs case conversion: [inline_collect.mbt:155](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/layout/inline_collect.mbt:155). An inserted UTF-8 prefix shifts an early visible glyph’s offset while that offset can still lie inside the original string. Repeated characters make even a substring comparison inconclusive. Preprocessing can also push an originally short string past the 16-bit limit; shaping additionally applies `span_offset` before saturation at [inline_shaping.mbt:637](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/layout/inline_shaping.mbt:637).

   **Fix:** Retain transformation/offset and overflow information from collection and shaping, or conservatively downgrade origins affected by preprocessing and offset adjustments. Establish exactness from a proven mapping, rather than from an in-range glyph offset.

4. **D — MAJOR: The report snapshot cannot resolve every diagnostic location it promises to retain.**

   [§14.2, design:984](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/docs/edsl-design.md:984) freezes listing entries and snippet texts, then promises to resolve every diagnostic, hint and trace against that snapshot.

   `Markup` can import/include ordinary Typst sources. Errors inside those files retain their own numbered source spans: [eval/import.mbt:240](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/eval/import.mbt:240), [eval/lib.mbt:35](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/eval/lib.mbt:35). Resolving those spans requires the corresponding source tree, as [engine.mbt:122](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/engine.mbt:122) shows. Neither synthetic-source table contains it. Also, the proposed `hints : Array[String]` cannot hold resolved hint locations, whereas engine hints are `DiagSpanned[String]`: [diag.mbt:41](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/diag.mbt:41).

   **Fix:** Persist resolved file/range information for ordinary and external-file diagnostics while their sources are available, or retain suitable source snapshots. Give hints a structured location-bearing representation. Keep the existing synthetic-origin ownership model.

5. **E — MINOR: Two context-capability claims are wrong.**

   §10.1 groups `counter.at` and `counter.final` under “context,” but `counter.final` explicitly requires a location: [counter.mbt:590](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/counter.mbt:590). It also says supplement callbacks receive the display-site context; they actually receive a newly constructed **styles-only** context: [reference.mbt:47](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/reference.mbt:47).

   **Fix:** Correct the capability table and callback descriptions; test these distinctions.

6. **F — MINOR: The structural-dump description overstates what the existing dumper records.**

   §16.2 calls it a dump of “all fields.” [Dumper::content](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/tests/runner/realize_stage.mbt:171) uses `Content::fields()`, which explicitly excludes internal fields at [content.mbt:324](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/content.mbt:324). It also identifies elements by non-unique local names.

   **Fix:** Extend the EDSL structural dumper to use unique element identities and raw stored fields, with explicit provenance normalization. Alternatively, narrow the stated guarantee and add separate assertions for excluded construction data.

7. **G — MINOR: Unit leaves use the wrong engine payload types.**

   §6.3 writes `Value::Length(Abs::pt(x))` and `Value::Ratio(x / 100)`. Their payloads are `Length` and `Ratio`, respectively: [value.mbt:16](/Users/dii/git/typst.mbt/.claude/worktrees/agent-a343352cbf9234c25/library/value.mbt:16).

   **Fix:** Write `Value::Length(Length::from_abs(Abs::pt(x)))` and `Value::Ratio(Ratio::new(x / 100))`. This preserves the chosen units API.
